# jev-guard enforce-mode A/B bench

n is small per arm (2-3) -- medians and ranges only, no significance claims.

## Smoke test (T1, trial "smoke", not counted in the tables below)

Ran one trial of each arm before the full sweep to prove the harness actually
separates enforcement from no-guard-at-all, by matching jev-guard's own log
(`~/.local/state/jev-guard/shadow.jsonl`) against each session's freshly
minted `session_id`:

- arm `jev`, session `<session-a>`: **1 guard log row**,
  `"mode": "enforce"`, `tool_name: "Bash"`, judging the `plocate ... .xlsm`
  command (`would_deny: false`, `enforced: false` -- correctly allowed, not a
  deny case).
- arm `none`, session `<session-b>`: **0 guard log
  rows** for that session_id -- the guard never ran at all.

Proof holds: `jev` really judges in enforce mode, `none` really judges
nothing.

## Cost checkpoint

First 6 sessions (all of task T1, both arms, 3 trials each) averaged
**$0.0554** in `total_cost_usd` -- well under the $0.60/session threshold, so
the full 3-trials-per-arm-per-task sweep ran as planned; no drop to 2 trials
was needed.

## Enforce-mode added latency (guard's own reported timing, not wall-clock)

Computed from every jev-guard log row's `elapsed_ms`/`latency_ms` in the
`jev` arm (n=16, one row per `PreToolUse` call the guard actually judged --
`Bash` calls for filename/code searches, `Agent` calls for the two
sub-agent-delegation tasks):

- **p50: ~327 ms**
- **p95: ~1116 ms**

The slower rows (1075-1124 ms) are all `Agent`-tool `tier_guard` judgments
(T4/T5's sub-agent dispatch); `Bash`-tool `tool_choice_guard` judgments
(T1-T3's file/code searches) cluster at 264-407 ms. Wall-clock deltas between
arms in the per-task tables below are dominated by ordinary task/model
variance (T4 in particular swung 82-281s in the jev arm from sub-agent search
depth, not guard overhead) and should not be read as the guard's cost --
the numbers above are.

## Denies, overrides, loop-allows, false denies

**Zero** denies, overrides, or loop-allows were emitted across all 30
sweep sessions (16 guard judgments total, all in the `jev` arm, all
`enforced: false`). None of these five tasks happened to trigger a genuine
block from the guard in enforce mode -- every command/sub-agent choice the
model made was one the guard agreed with. Consequently there is nothing to
report for "what the agent did after a deny" (switch to plocate/graphify,
use the override stamp, get loop-allowed) and **no false denies occurred**
(none to list).

## Harness bug found and fixed mid-run

`bench/tasks.py::check_t5` compared the post-edit scratch file's original
counterpart against a pinned baseline at `/tmp/jev-bench/silence_alert.py`
that `bench/run.py` never actually creates (it only ever writes
`silence_alert_<uuid>.py` scratch copies) -- so the "original repo file
untouched" check always raised `FileNotFoundError` and every T5 trial was
marked incorrect regardless of the actual edit. Confirmed via `git diff
--quiet` that the real `example-app` source was clean (untouched) before
fixing. Fixed by lazily pinning the baseline on first use, refusing to pin if
the source has uncommitted changes. Re-ran the checker against the two T5
trials that completed before the fix (their scratch files were still on
disk) -- both were actually correct (docstring present) and are recorded as
such below; the remaining four T5 trials ran fresh under the fixed checker.
